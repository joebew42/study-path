# Fix broken links to the OCP, LSP, ISP and DIP articles

GitHub Issue: https://github.com/joebew42/study-path/issues/54

## Context

In the `## 📐 Session 1: SOLID and Clean Code` section of `readme.md`, four of the five
SOLID principle articles hosted on Google Docs point at a legacy URL format that Google
no longer supports. Opening them lands on a "No preview available" page:

```
http://docs.google.com/a/cleancoder.com/viewer?a=v&pid=explorer&chrome=true&srcid=<DOC_ID>&hl=en
```

The SRP link in the same list (line 39) already uses the modern format and works:

```
https://docs.google.com/open?id=<DOC_ID>
```

So the fix is a mechanical rewrite of the four remaining links to the format the list
already uses elsewhere.

## Scope

`readme.md`, lines 40–43 only. Four link URLs. No link text, no list structure, no other
section is touched.

| Line | Principle | Document ID |
| --- | --- | --- |
| 40 | OCP: Open-Closed Principle | `0BwhCYaYDn8EgN2M5MTkwM2EtNWFkZC00ZTI3LWFjZTUtNTFhZGZiYmUzODc1` |
| 41 | LSP: Liskov Substitution Principle | `0BwhCYaYDn8EgNzAzZjA5ZmItNjU3NS00MzQ5LTkwYjMtMDJhNDU5ZTM0MTlh` |
| 42 | ISP: Interface Segregation Principle | `0BwhCYaYDn8EgOTViYjJhYzMtMzYxMC00MzFjLWJjMzYtOGJiMDc5N2JkYmJi` |
| 43 | DIP: Dependency Inversion Principle | `0BwhCYaYDn8EgMjdlMWIzNGUtZTQ0NC00ZjQ5LTkwYzQtZjRhMDRlNTQ3ZGMz` |

Each becomes `https://docs.google.com/open?id=<DOC_ID>`.

Out of scope: replacing the Google Docs hosting with another source, reviewing any other
link in `readme.md`, and adding link-checking automation.

## Acceptance criteria

- [x] All five SOLID principle links in Session 1 use the `https://docs.google.com/open?id=` form.
- [x] Each of the four rewritten URLs resolves with HTTP 200 and renders the article.
- [x] The link texts, the ordering (SRP → OCP → LSP → ISP → DIP), and the surrounding
      list structure are unchanged.
- [x] `git diff` touches exactly four lines in `readme.md`.

## Implementation notes

The repository is a curated markdown study path — there is no build, test suite, or
linter. Verification is therefore: the `grep` check above, a read of `git diff`, and an
HTTP status check of the four URLs.

Prior verification (already run during planning) confirmed all four rewritten URLs return
`200`, matching the behaviour of the working SRP link.

## Progress

- [x] Rewrote the OCP, LSP, ISP and DIP URLs in `readme.md` (lines 40–43) from the legacy
      `docs.google.com/a/cleancoder.com/viewer?...&srcid=<ID>&hl=en` form to
      `https://docs.google.com/open?id=<ID>`.

All acceptance criteria verified: `grep` for the legacy form returns nothing, the diff is
exactly 4 changed lines in `readme.md`, and all five SOLID links (including the untouched
SRP one) return HTTP 200.

### Decisions

- Applied as a single `sed` rewrite capturing the document ID, rather than four separate
  edits — the four links differ only by ID, so one regex covers them without transcription
  risk.
- Links were also upgraded from `http://` to `https://`, matching the SRP link that was
  already correct.
- No link-checking automation was added; the repo has no CI, build or test harness, and the
  spec put that out of scope.

Nothing remaining.
